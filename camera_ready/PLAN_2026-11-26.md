# 2026-11-26 22:00 KST 기준 실행 분담

**완료 확인:** 로컬 핵심 18회는 2026-11-26 18:54 KST에 모두 완료됐으며 실패·추가 반납 작업은 없습니다. 다른 환경 배정 완료를 뜻하지 않습니다. [3-seed 결과](results/latest/THREE_SEED_RESULTS_KO.md)와 [완료 상태](results/latest/PROGRESS_KO.md)를 확인합니다.

이 계획이 이번 실행의 작업 배정 기준입니다. 이전 전체 순차 큐와 48시간 로컬 평가 계획은 교체했습니다. 기계가 읽는 목록은 [allocation_2026-11-26.json](allocation_2026-11-26.json)입니다.

| 환경 | 배정 | 종료 / 의존성 |
|---|---|---|
| 현재 H100 80GB × 2 | 핵심 6조건 × seeds 1,2,3 = **18회 학습 우선 처리** | **2026-11-26 22:00 KST**까지 |
| 다른 환경 | `whole_gate`, `q_resample`, `component_zvp` × seeds 1,2,3 = **9회 학습** | 지금부터 독립적으로 실행 가능 |
| 다른 환경 | base 1개 + 핵심 18개 체크포인트의 **19개 모델 확장 평가** | 해당 adapter를 받는 대로 실행 가능 |
| 다른 환경 추가 대기열 | 현재 서버가 시간 부족/오류로 반납한 핵심 run | 최신 `live_handoff.json`의 `remote_fallback_jobs`만 사용 |

확장 평가는 모델마다 **4,138개 입력**입니다. 두 새 평가셋은 원문 기준 2,069문제이며 번역과 seed를 독립 문제로 세지 않습니다. 원격에서 즉시 실행할 9개 학습과 로컬 18개 학습은 겹치지 않습니다.

## 현재 서버 운영

현재 병렬 관리자는 이미 실행했습니다. GPU마다 최대 네 독립 학습 프로세스를 사용합니다. 기존 `vanilla_s1_n100`, `split_s1_n100`의 PID와 학습 진행은 보존했습니다. G=4, 추가 응답 2개, prompt batch, optimizer, 100 steps, seed와 보상 계산은 바꾸지 않았습니다.

전환 후 GPU당 약 66–70GB, GPU utilization 100%가 관측됐습니다. 여유 메모리가 부족하면 새 작업을 시작하지 않으며, entropy 대조군이 포함된 GPU는 최대 세 작업으로 제한합니다. 독립 프로세스 간 속도 변화가 있으므로 이 수치만으로 처리량 배수를 주장하지 않습니다.

아래는 현재 실행에 사용한 명령 형태입니다. **로컬 배정은 이미 완료됐으므로 현재 서버에서 다시 실행하지 않습니다.**

```bash
python camera_ready/run_parallel.py --gpus 0,1 --workers-per-gpu 4 \
  --allocation camera_ready/allocation_2026-11-26.json --role local \
  --output /path/to/paper_eacl/camera_ready_experiments/runs \
  --state-dir /path/to/paper_eacl/camera_ready_experiments \
  --adopt-state /path/to/paper_eacl/camera_ready_experiments/serial_status_before_parallel.json
```

새 run에는 보수적으로 210분과 종료 여유 25분을 배정합니다. 기본 설정에서는 **18:05 KST 이후 새 run을 시작하지 않습니다.** 남은 미시작 작업은 로컬 예약에서 해제해 원격 목록에 내보냅니다. 이미 실행 중인 작업은 완료를 계속 시도합니다. 22:00에도 남아 있는 이 실험의 학습 프로세스는 종료하고 파일을 보존해 원격 재실행 목록에 넣습니다. 다른 프로젝트의 프로세스는 건드리지 않습니다.

`live_handoff.json`과 `LIVE_HANDOFF.md`는 현재 서버의 `camera_ready_experiments/`에 갱신됩니다. `pending`은 아직 로컬에 예약된 작업이며 원격에서 먼저 시작하지 않습니다. **`remote_fallback_jobs`만 명시적으로 반납한 작업**입니다. GitHub의 `SOURCE_STATUS.json`은 게시 시점 스냅샷입니다.

## 다른 환경에서 지금 실행

설치는 [README_KO.md](README_KO.md)의 1–3절을 따릅니다. 같은 Git commit, 패키지 버전, 고정 모델 revision을 사용합니다. 이 사전 분담에는 현재 서버를 정지하는 `source_handoff.py`를 실행할 필요가 없습니다.

```bash
source .venv/bin/activate
# GPU 한 장이면 --gpus 0. 다른 장비에서는 먼저 verify와 smoke 실행.
python -u camera_ready/run_parallel.py --gpus 0,1 --workers-per-gpu 4 \
  --allocation camera_ready/allocation_2026-11-26.json --role remote \
  --output outputs/remote_controls --state-dir outputs/remote_state \
  > remote_parallel.log 2>&1
```

원격에서도 같은 engine을 사용합니다. 완료된 동일 설정의 작업은 건너뜁니다. 미완료 디렉터리는 보존하고 해당 run을 처음부터 다시 시작합니다.

## 반납된 로컬 작업 추가 인계

현재 서버의 최신 `live_handoff.json`을 다른 환경에 복사한 뒤:

```bash
python camera_ready/make_fallback_allocation.py \
  --source-state received/live_handoff.json \
  --output outputs/fallback_allocation.json
python -u camera_ready/run_parallel.py --gpus 0,1 --workers-per-gpu 4 \
  --allocation outputs/fallback_allocation.json --role remote \
  --output outputs/remote_controls --state-dir outputs/fallback_state \
  > remote_fallback.log 2>&1
```

반납 작업이 없으면 첫 명령은 실행할 작업이 없다고 종료합니다. optimizer/RNG 상태 복원은 지원하지 않으므로 반납된 미완료 run은 원격에서 seed 초기화부터 100 steps를 실행합니다.

## 결과와 adapter 전달

각 환경의 결과를 별도 staging 경로로 복사하고 원본은 보존합니다. 외부 평가에는 adapter도 필요합니다.

```bash
python camera_ready/merge_results.py \
  --roots received/local/runs outputs/remote_controls \
  --destination outputs/merged --with-adapters
```

이후 [README_KO.md](README_KO.md)의 8절 확장 평가를 다른 환경에서 실행합니다. GPU 두 장이면 세 조건씩 나누고 base는 한 번만 평가합니다. 단일 GPU에서는 `--include-base`를 포함해 여섯 조건을 순서대로 평가합니다. 완성된 같은 tag를 덮어쓰지 않습니다.

현재 서버에서는 확장 평가를 시작하지 않습니다. 22시 전 GPU 시간은 핵심 학습에 사용합니다. 최종 통계와 LaTeX 표는 모든 요청된 arm/seed를 취합한 뒤 생성합니다.
